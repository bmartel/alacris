Alacris

alacer / alacris — brisk, lively, quick

Web components with signals and fine-grained DOM updates. Every widget below is a real custom element — no virtual DOM, no build step.

docs playground github npm browser tests

Counter — props, computed, events

start is a live prop. Changing it from outside (or the interop section below) follows through; the doubled value is a computed. 

<ala-counter start="3"></ala-counter>

Nested components — live props down the tree

The parent owns the roster. Each card is a child custom element that receives the person object and a displayName string. Edit a name or pick another row — the children update in place, no re-render of the parent setup. 

html`<ala-person person=${p} displayName=${() => p().name} highlight=${() => selected() === p().id}>`

Todos — each, two-way input

Rows are keyed. Shuffle moves the existing DOM nodes, so checkboxes keep their state.

Store — deep paths, O(1) selection

Mutating state.rows[1].label writes one text node. Selection uses selector so only the two involved rows wake up.

Context — skip the prop drill

The leaf is two shadow roots down and never receives the theme as a prop. It consumes the W3C context-request protocol.

Interop — driven from plain JavaScript

An Alacris element is just a DOM element: set properties, listen for events. This is the same ala-counter as above.

Styling — theming from outside the component

The chip declares a vars() contract. A consumer overrides it with plain CSS, adoptGlobal, or ::part — never !important.

default warn ok 

/* the consumer writes plain CSS, no library involved */
ala-chip            { --chip-bg: #2b2b33 }
ala-chip::part(dot) { width: 14px }

Stress — 1,000 keyed rows

each diffs the snapshot untracked, so editing one label does not rebuild the list.
