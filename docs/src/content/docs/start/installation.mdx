Alacris is ESM-only and has no dependencies. There is nothing to configure.

## From a CDN

The fastest way to try it, and a perfectly good way to ship it. No bundler, no
install:

```html
<script type="module">
  import { define, html, signal } from 'https://unpkg.com/alacris';

  define('hello-world', () => html`<p>hello</p>`);
</script>

<hello-world></hello-world>
```

<Aside type="tip" title="Pin the version in production">
`https://unpkg.com/alacris` always resolves to the newest release. For anything
you ship, pin it so an upgrade cannot surprise you:

```js
import { define } from 'https://unpkg.com/alacris@0.10.0/dist/alacris.js';
```
</Aside>

## From npm

```sh
npm install alacris
```

```js
import { define, html, signal, computed, effect } from 'alacris';
import { store, selector } from 'alacris/store';
import { createContext, provide, consume } from 'alacris/context';
```

TypeScript declarations ship with the package. There is nothing to add.

## A component library, not a blank runtime

If you want buttons, fields, and a theme rather than starting from
`define(...)`, copy the [UI starter](../ui-starter/) out of the repo. It is a
template — sixty-odd custom elements and a theme engine — not a second npm
package.

## The entry points

Add-ons import the core rather than bundling it, so there is exactly one
reactive graph at runtime however many you use.

  <thead>

  </thead>
  <tbody>
    <tr><td>`alacris`</td><td>signals, templates, styling, custom elements</td><td>6.56 kB</td></tr>

If you use a bundler, anything you do not import is tree-shaken away — the
package is marked `sideEffects: false`.

<Aside type="caution" title="Do not mix `alacris` and `alacris/signal`">
`alacris/signal` is a standalone build for non-DOM use, such as a worker or a
server. It carries its own copy of the reactive core, so signals created with it
are in a *different* dependency graph from anything rendered by `alacris`. If
you are rendering, import your signals from `alacris`.
</Aside>

## Browser support

Alacris uses `<template>`, `TreeWalker`, custom elements and — for `styles` —
constructable stylesheets, with a `<style>` fallback where those are missing.

That means Chrome and Edge 86+, Safari 16.4+, and Firefox 101+. There are no
polyfills and no transpiled build; the published code is modern ESM.
