Alacris is ESM-only and has no dependencies. There is nothing to configure.

## From a CDN

The fastest way to try it, and a perfectly good way to ship it. No bundler, no
install:

```html
<script type="module">
  import { define, html, signal } from 'https://unpkg.com/@alacris/core';

  define('hello-world', () => html`<p>hello</p>`);
</script>

<hello-world></hello-world>
```

<Aside type="tip" title="Pin the version in production">
`https://unpkg.com/@alacris/core` always resolves to the newest release. For anything
you ship, pin it so an upgrade cannot surprise you:

```js
import { define } from 'https://unpkg.com/@alacris/core@0.11.0/dist/alacris.js';
```
</Aside>

## From npm

```sh
npm install @alacris/core
```

```js
import { define, html, signal, computed, effect } from '@alacris/core';
import { store, selector } from '@alacris/core/store';
import { createContext, provide, consume } from '@alacris/core/context';
```

TypeScript declarations ship with the package. There is nothing to add.

<Aside type="note" title="Renamed from `alacris`">
The runtime used to be the unscoped `alacris` package. It is now `@alacris/core` — same API, new specifier. The design system is a separate package, [`@alacris/ui`](../../ui/getting-started/).
</Aside>

## A component library, not a blank runtime

If you want buttons, fields, and a theme rather than starting from
`define(...)`, install [Alacris UI](../../ui/getting-started/) (`@alacris/ui`
on npm). It is sixty-eight custom elements and a theme engine, and it works
in any framework that can render a tag.

## The entry points

Add-ons import the core rather than bundling it, so there is exactly one
reactive graph at runtime however many you use.

  </thead>
  <tbody>
    <tr><td>`@alacris/core`</td><td>signals, templates, styling, custom elements</td><td>6.56 kB</td></tr>

If you use a bundler, anything you do not import is tree-shaken away — the
package is marked `sideEffects: false`.

<Aside type="caution" title="Do not mix `@alacris/core` and `@alacris/core/signal`">
`@alacris/core/signal` is a standalone build for non-DOM use, such as a worker or a
server. It carries its own copy of the reactive core, so signals created with it
are in a *different* dependency graph from anything rendered by `@alacris/core`. If
you are rendering, import your signals from `@alacris/core`.
</Aside>

## Browser support

Alacris uses `<template>`, `TreeWalker`, custom elements and — for `styles` —
constructable stylesheets, with a `<style>` fallback where those are missing.

That means Chrome and Edge 86+, Safari 16.4+, and Firefox 101+. There are no
polyfills and no transpiled build; the published code is modern ESM.
