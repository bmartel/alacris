Alacris is the runtime. The **UI starter** is a complete design system built
with it: buttons, fields, pickers, dialogs, navigation, a three-tier token
system, and a theme engine that re-skins the whole page with one stylesheet
write. Material Design is the default. Your design system is the point.

It lives in [`starter/`](https://github.com/bmartel/alacris/tree/main/starter)
in the Alacris repo. It is a template, not a published package — copy the
folder into your project and own it.

## Try it here

From a clone of the [Alacris repo](https://github.com/bmartel/alacris):

```sh
npm install
npm run demo
```

Open `http://localhost:5173/starter/`. That page is the kitchen sink: every
component, plus a live theme playground. The demo itself is a worked example
of composing the system — `starter/demo/` is worth reading.

## Copy it into an app

Copy `starter/` out of the repo. Point `alacris` at a pinned CDN build or at
the npm package — the source is identical in both setups.

## Boot a page

Theme first, so the first paint is already themed, then register the
elements:

```js
import { applyTheme } from './src/theme/index.js';
import './src/index.js';

applyTheme({ seed: '#0b57d0' });
```

```html
<ui-button>Hello</ui-button>
<ui-text-field label="Email" clearable></ui-text-field>
<ui-switch label="Dark mode"></ui-switch>
```

`src/index.js` imports every component module (registration is a side effect)
and re-exports the theme, motion, token, and utility APIs. For a smaller
page, import only the files you use — each component module is
self-contained:

```js
import { applyTheme } from './src/theme/index.js';
import './src/components/ui-button.js';
import './src/components/ui-text-field.js';

applyTheme({ seed: '#0b57d0' });
```

The tags are real custom elements, so they work in plain HTML and inside
React, Vue, Svelte, Rails, Django — anywhere that renders tags. See
[Using it from a framework](../../guides/frameworks/).

## Theming

Every visual decision flows through CSS custom properties in three tiers.
Components never hardcode a colour, radius, or duration — they speak only
`sys.*` tokens — so a theme change restyles everything without a re-render.

```js
import { createTheme, applyTheme, setScheme, toggleScheme } from './src/theme/index.js';

applyTheme({ seed: '#6750a4' });
applyTheme({ seed: '#b3261e', density: -1 });
setScheme('dark');
toggleScheme();

applyTheme(createTheme({
  colors: { primary: '#0b57d0', tertiary: '#00695c' },
  typography: { brand: 'Inter, sans-serif', scale: 1.05 },
  shape: { radius: 0.5 },
  overrides: { light: { 'color-surface': '#faf7f2' } },
}));
```

`applyTheme` writes **one** document-level stylesheet of `--ui-*` custom
properties and replaces it in place on the next call. Scheme switching after
that is `data-ui-scheme` on `<html>` (`light` | `dark` | `auto`).

Three places to intervene, from broadest to narrowest:

1. **Re-theme the system** — `applyTheme({ seed, shape, … })`. Every component
   follows. Dark mode is generated automatically.
2. **Re-skin one component type** — set its contract in CSS:
   `ui-button { --ui-button-radius: 4px; }`.
3. **Reach inside one instance** — exposed parts:
   `ui-dialog::part(surface) { backdrop-filter: blur(8px) }`.

The last two are the same [consumer theming contract](../../guides/theming/)
Alacris itself teaches (`vars()`, `::part`). The starter adds the first
layer: a generated Material-shaped palette and a `sys` accessor so components
never write raw `var(--ui-…)` strings.

Material is one file deep at every layer. Swap the type scale in
`tokens/typography.js`, the shape ramp in `tokens/system.js`, the role mapping
in `tokens/color.js` — or leave the machinery alone and pass
`createTheme(...)`. The
[theming guide in the starter](https://github.com/bmartel/alacris/blob/main/starter/docs/theming.md)
walks through a full re-skin.

## Forms and motion

Named controls (`ui-text-field`, `ui-switch`, `ui-checkbox`, `ui-select`, …)
are **form-associated custom elements**. The browser treats them as real
fields via `ElementInternals`: they submit, reset to the initial value, and
follow `<fieldset disabled>`. Give a component a `name` and it submits like a
native field.

Durations and easings are tokens, so the theme's `motion.scale` governs CSS
transitions and JS animation alike, and `prefers-reduced-motion` is honoured
automatically:

```js
import { animate, fx, presence, withFlip } from './src/motion/index.js';

animate(el, fx.slideInUp, { duration: 'medium2', easing: 'emphasizedDecelerate' });

html`${presence(open, () => html`<div class="sheet">…</div>`, {
  enter: fx.slideInUp, exit: fx.slideOutDown,
})}`;
```

`presence` is the exit-animation hook fine-grained rendering does not give
you on its own. The
[motion guide](https://github.com/bmartel/alacris/blob/main/starter/docs/motion.md)
covers presets, FLIP reorders, and ripple.

## Adding a component

Read [`CONVENTIONS.md`](https://github.com/bmartel/alacris/blob/main/starter/CONVENTIONS.md)
before writing one. The short version: tag prefix `ui-`, one file per
element, consume tokens only through `sys`, declare the public contract with
`vars('ui-thing', …)`, include `base` in `styles`, and keep the file-header
comment accurate — the
[component catalog](https://github.com/bmartel/alacris/blob/main/starter/docs/components.md)
is assembled from those headers.

## What's in the folder

```
starter/
  index.html            kitchen-sink demo + live theme playground
  src/
    index.js            registers every component; public API surface
    tokens/             palettes, type, shape, elevation, motion, sys
    theme/              createTheme / applyTheme / scheme switching
    motion/             animate, fx, presence, withFlip, ripple
    util/               positioning, focus trap, formBind, icons
    components/         one file per <ui-*> element
  demo/                 the demo app — a worked example
  docs/                 theming, motion, and the component catalog
  CONVENTIONS.md        rules every component follows
```
